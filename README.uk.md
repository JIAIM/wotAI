# WoT Spawn Advisor

![tests](https://github.com/JIAIM/wotAI/actions/workflows/tests.yml/badge.svg)

[English](README.md) · **Українська**

Ігровий мод для **World of Tanks**, який на початку бою позначає на мінікарті **топ-3 стартові позиції**: де варто бути приблизно на 90-й секунді для поточної карти та сторони респу. Поради отримано з ~4 000 розібраних реплеїв боїв.

Проєкт зроблено власноруч для навчання та портфоліо: від парсера бінарних реплеїв до оцінювання моделі й робочого моду для клієнта гри.

```
реплеї (.wotreplay) ──► парсер ──► датасет ──► ознаки ──► оцінки зон ──► топ-3 на карту/сторону ──► .wotmod
                                                  │
                                                  └──► ноутбуки: бейзлайн, модель, експерименти з класами та ролями
```

## Результат в одному абзаці

Гравці, які на 90-й секунді стоять в одній із трьох рекомендованих зон, завдають у середньому в **1,33–1,38 раза більше шкоди відносно своєї команди**, ніж союзники деінде (590 відкладених боїв). Три спроби персоналізувати пораду — за складом команди (градієнтний бустинг), за класом танка та за роллю танка — **не перевершили єдину теплову карту для кожної карти**. Хороші зони на карті спільні для всіх; як там грати (перша чи друга лінія) — справа конкретного танка.

## Як це працює

### 1. Парсер реплеїв (`src/spawn_advisor/replay/`)
Написаний з нуля, без сторонніх бібліотек для реплеїв.

- **Контейнер**: magic `0x11343212`, JSON-блоки (заголовок бою та результати), далі зашифрований потік пакетів.
- **Шифрування**: Blowfish-ECB з публічним ключем реплеїв; кожен 8-байтовий блок XOR-иться з попереднім розшифрованим блоком; далі zlib.
- **Пакети**: `[size u32][type u32][time f32][payload]`. Використовуються типи: назва карти (15), склад бою (50), позиції об'єктів (10), зміна періоду бою (8).
- **Початок бою** визначається *за вмістом* (pickle-кортеж періоду `(3, …)`), бо ідентифікатор методу різний у різних версіях клієнта. Pickle читається через `SafeUnpickler`, який відмовляється створювати будь-які класи.
- Працює на клієнтах 2.0–2.4.1. Результати кешуються для кожної версії парсера.

### 2. Датасет і ознаки (`dataset.py`, `features.py`, `tankopedia.py`, `roles.py`)
- Один рядок на кожен союзний танк: позиція на 90-й секунді, чи живий на 90-й секунді, шкода, допомога, засвіт, перемога.
- Клас і рівень танка — з WG Tankopedia API; **ролі** танків (штурмова/снайперська ПТ, ПТ підтримки, проривний ВТ, …) — з упакованого BigWorld XML у `scripts.pkg` клієнта гри.
- Ціль: `damage_rel` = шкода танка / середня шкода в його бою (рахується до фільтрації).
- Фільтри: випадкові бої у стандартному режимі (`ctf`), без ботів, живий на 90-й секунді, клієнт 2.x.
- Підсумкова таблиця: **57 959 рядків, 4 075 боїв**; поради охоплюють 45 карт. Кожна карта поділена на зони 100×100 м.

### 3. Рекомендація (`recommend.py`)
Згладжена теплова карта для кожної трійки (карта, сторона, зона):

```
score = (Σ damage_rel + K·1.0) / (n + K),   K = 50,  лише зони з n ≥ 10
```

Далі жадібний вибір 3 найкращих зон, віддалених одна від одної щонайменше на 200 м.

### 4. Доставка
- **`mod/`** — мод для клієнта (Python 2.7). Перехоплює компонент мінікарти й малює кольорові векторні кільця (фіолетове/бірюзове/зелене = 1/2/3 місце) тим самим елементом мінікарти, яким гра малює кола огляду. F9 вмикає/вимикає. Для арти приховано.
- **`live.py`** — рання зовнішня версія: стежить за `temp.wotreplay`, визначає карту та сторону з перших пакетів (152/152 правильно) і показує графік.

## Оцінювання

**Розбиття за боями**, а не за рядками: усі союзники одного бою потрапляють або в навчання, або в перевірку. Зафіксований список із 3 485 «робочих» боїв використовується для всіх налаштувань через 5-кратну крос-валідацію; **590 новіших боїв** відкладено й перевірено один раз на кожен експеримент.

**Метрика — lift**: середній `damage_rel` танків, які на 90-й секунді *були* в рекомендованій зоні, поділений на середній у тих, хто не був. Спершу пробував MAE, але вона обирала параметри, що погіршували продукт; lift вимірює продукт напряму.

| Експеримент | Lift на CV (робочі бої, 5 фолдів) | Lift на відкладених (590 боїв) | Ноутбук |
|---|---|---|---|
| Згладжена теплова карта, топ-3 | **1.325 ± 0.018** | **1.384** | 02 |
| Окрема теплова карта для кожного класу | 1.214 ± 0.027 | — | 02 |
| HistGradientBoosting (клас, рівень, склад команди, апріорна оцінка зони) | 1.296 ± 0.020 | 1.342 | 03 |
| Версія продукту (топ-3 з відстанню 200 м) | 1.289 ± 0.016 | 1.332 | 04 |
| За класом, зі згладжуванням до карти (K = 50) | 1.289 ± 0.016 | 1.342 | 04 |
| За роллю, зі згладжуванням до карти (K = 50) | 1.285 ± 0.016 | 1.311 | 05 |

Різниця між трьома останніми рядками в межах розкиду між фолдами; жодна сила згладжування (K від 0 до 200) не дала виграшу, більшого за цей розкид.

Інші висновки:
- Склад команд за класами однаковий в обох команд у **96,7%** боїв, тож «склад супротивника» нічого не додає.
- Lift спільної поради позитивний для кожної ролі, наприклад ПТ підтримки (на кшталт FV4005) **1,36**, снайперські ПТ 1,27, проривні ВТ 1,25.
- **Арта: lift ≈ 0,98** — порада не допомагає, тому мод її для САУ приховує.
- Легкі танки: якщо міряти їхній внесок як шкоду + шкоду за засвітом, спільна порада їм нічого не дає (0,98), а зони, обрані за цією метрикою, дають 1,21 ± 0,06. У мод не додано: що важливіше для ЛТ — це рішення щодо продукту, а не висновок із даних.

## Обмеження

- **Зв'язок, а не причина.** Можливо, сильніші гравці просто обирають ці зони. Наступний крок — порівняння в межах одного гравця або поправка на його рівень гри.
- **Зміщена вибірка.** ~77% боїв у даних — перемоги: реплеї, якими діляться та які записують, частіше показують вдалі бої й сильних гравців.
- **Грубо.** Зони 100 м і один знімок на 90-й секунді не розрізняють «першу лінію» та «другу лінію» в одній місцевості.
- Режими «Зустрічний бій» і «Штурм», Генеральні бої та карти з малою кількістю даних не охоплені.

## Дані

Сирі реплеї **не** зберігаються в цьому репозиторії: у них нікнейми інших гравців.

| Джерело | Реплеїв |
|---|---|
| Власні реплеї та реплеї друзів | 1 370 |
| wot-record.com | 3 898 |

Реплеї з wot-record.com завантажено скриптом (`download_replays*.py`), який перебирає ідентифікатори реплеїв. `robots.txt` сайту забороняє автоматичний доступ до `/download/`, і дозволу від власника сайту не отримано. Хто відтворюватиме цю роботу, має спершу запитати власника сайту або використати власні реплеї.

## Запуск

```bash
python -m venv .venv && .venv\Scripts\activate
pip install -e ".[dev]"
pytest -q

# повне перезбирання: реплеї в data/raw/<джерело>/ → датасет → ознаки → поради → мод
python -m spawn_advisor.release                  # для моду потрібен Python 2.7 як `py -2.7`
python -m spawn_advisor.release --skip-dataset   # узяти вже розібрані дані
python -m spawn_advisor.roles "<WoT>\res\packages\scripts.pkg"   # ролі танків для ноутбука 05
```

Для Tankopedia потрібен безкоштовний application id WG API у `.env` як `WG_APPLICATION_ID=...`.

**Встановлення моду:** скопіюйте `dist/spawn_advisor_<версія>.wotmod` у `World_of_Tanks\mods\<версія гри>\`. Налаштування (кольори, розмір кілець, клавіша, показ для арти) — константи на початку `mod/mod_spawn_advisor.py`.

## Структура репозиторію

```
src/spawn_advisor/replay/   парсер: контейнер, шифрування, пакети, позиції, початок бою
src/spawn_advisor/          датасет, ознаки, tankopedia, ролі, рекомендації, live, реліз
mod/                        мод клієнта + скрипт збирання (.py → .pyc Python 2.7 → .wotmod)
notebooks/                  01 EDA · 02 бейзлайн · 03 модель · 04 поради за класом · 05 ролі
tests/                      pytest, з невеликими реплеями-фікстурами
```

## Можливі наступні кроки

1. Врахувати рівень гравця (порівняння в межах одного гравця), щоб перевірити, чи порада *спричиняє* більшу шкоду.
2. «Перевантажений фланг»: чи лишається зона хорошою, якщо туди вже поїхало багато союзників? Це була б перша порада, що залежить від конкретного бою.
3. Дрібніші зони (50 м або оцінка щільності ядром), щоб розрізнити першу й другу лінії.
